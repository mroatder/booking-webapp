# UI Style Guide - กติกาบังคับของทุกหน้าจอ

> **ใช้กับทุกงาน**: หน้าใหม่ ฟีเจอร์ใหม่ และการแก้ไขหน้าเดิม ต้องได้หน้าตาเดียวกันทั้งระบบ
> ตรวจอัตโนมัติด้วย `npm run lint:ui` (ใน `frontend/`) - ต้องผ่านก่อน commit ทุกครั้งที่แตะไฟล์ `.vue` หรือ `style.css`
> ที่มาของกติกา: ผ่านการออกแบบและอนุมัติจาก dev (ต.ค. 2026) - ต้นแบบที่อนุมัติคือหน้า **จัดการแผนก** (`views/admin/DepartmentsView.vue`) ให้ดูหน้านั้นเป็นตัวอย่างเสมอ

## 1. หลักการ (ห้ามฝ่าฝืน)

1. **ขาวสด ดำคม + สีเน้น 1 สี + สีสถานะชุดเดียว** - พื้นขาวล้วน ตัวอักษรดำเกือบสนิท สีเน้น (accent) ใช้เฉพาะ "สิ่งที่กดได้/สิ่งที่เลือกอยู่" ไม่ใช้ตกแต่ง; **ใช้หลายสีได้เมื่อสื่อสถานะ** (dev ยืนยัน 2026-10-14): ฟ้า (`sky`/`blue`) = ข้อมูล/กำลังใช้, เขียว (`emerald`/`green`) = สำเร็จ/ว่าง, เหลืองอำพัน (`amber`) = รอ/เตือน, แดง (`red`) = ผิด/ปฏิเสธ — ใช้เป็นพื้นอ่อน (`-50`/`-100`) + ตัวอักษรเข้ม (`-700`/`-800`) ไม่ต้องมีขอบสี; สเกลสีเหล่านี้ถูกจูนชุดเดียวใน `style.css` ห้ามใช้ hex สีอื่นเอง
2. **ขอบน้อยที่สุด** - แบ่งส่วนด้วย พื้นสีอ่อน + ช่องว่าง ก่อนเสมอ เส้นขอบใช้เมื่อจำเป็นจริงเท่านั้น (เช่น ช่องกรอก) - เมนูย่อยไม่มีเส้นคั่นด้านล่าง มีแค่เส้นใต้ของรายการที่เปิดอยู่
3. **ไม่ลอย** - ตาราง/เนื้อหาวางแบนบนพื้นขาว ไม่มีกรอบการ์ดมีเงา (เงาใช้เฉพาะ modal / dropdown / toast)
4. **มุมโค้งปานกลาง 2 ระดับเท่านั้น** - `rounded-control` (8px: ปุ่ม ช่องกรอก แถบกลุ่ม) และ `rounded-card` (12px: แผงใหญ่); modal ใช้ `modal-panel`; ชิป/ตัวกรองเป็นแคปซูล (`rounded-full`) - ห้ามเหลี่ยมสนิทและห้ามโค้งอย่างอื่น
5. **สีผิด/อันตราย = แดงเท่านั้น** (`danger`) และแสดงเมื่อเกิดเหตุจริง (ปุ่มลบเป็นเทา เปลี่ยนแดงตอน hover) - สีส้มแดงของโลโก้ the company ใช้ที่โลโก้เท่านั้น
6. **ไอคอน** = `components/common/AppIcon.vue` เท่านั้น (ดู REQUIREMENTS § 7) ห้ามอีโมจิ ห้ามวาง SVG เอง

## 2. Token (ประกาศใน `frontend/src/style.css` ส่วน `@theme` - ที่เดียวเท่านั้น)

| Token | ค่า | ใช้กับ |
|---|---|---|
| `ink` | `#050505` | ข้อความหลัก, หัวตาราง |
| `muted` | `#3f3f3f` | ข้อความรอง |
| `subtle` | `#8a8a8a` | placeholder, ไอคอนจาง, คำอธิบายเล็ก |
| `line` | `#e4e4e4` | เส้นคั่นที่จำเป็น |
| `hair` | `#f0f0f0` | เส้นบางสุด คั่นแถวย่อยที่ติดกัน |
| `field` | `#c6c6c6` | ขอบช่องกรอก / ปุ่มรอง |
| `surface` | `#f1f1f1` | แถบกลุ่ม, ชิป, ช่องค้นหา |
| `canvas` | `#fafafa` | พื้น hover |
| `accent` / `accent-strong` / `accent-soft` | `#050505` / `#3f3f3f` / `#ececec` | สีเน้น (ปัจจุบันเป็นดำ) (ปุ่มหลัก, เมนูที่เปิด, focus, ชิปเลือก) |
| `danger` | `#d0141b` | ลบ / error |

ใช้เป็น utility ปกติ: `text-ink`, `text-muted`, `bg-surface`, `border-line`, `text-accent`, `bg-accent-soft` ฯลฯ

**เปลี่ยนสีเน้นทั้งระบบ**: แก้ 3 ค่า `--color-accent*` ที่เดียว (ตัวเลือกที่เคยเทียบแล้ว: Cobalt `#0a3cff`, Teal `#007c70`, Violet `#5a2dff`, Emerald `#00843c`, Signal `#f03a0a`)

> สเกล `slate-*` ของ Tailwind ถูกปรับค่าเป็นขาว-ดำคมแล้ว หน้าเก่าที่ยังใช้ `slate-*` จึงหน้าตาเท่ากับหน้าใหม่ - แต่ **ไฟล์ใหม่ห้ามใช้ `slate-*`** ให้ใช้ token ด้านบน

## 3. Component class (ประกาศใน `style.css` ส่วน `@layer components`) - ใช้ชื่อเหล่านี้ ห้ามเขียนซ้ำเอง

| ต้องการ | ใช้ |
|---|---|
| ปุ่มหลัก (1 ต่อหน้า/กล่องโต้ตอบ) | `btn btn-primary` |
| ปุ่มรอง / ยกเลิก | `btn btn-secondary` |
| ปุ่มอันตรายที่ยืนยันแล้ว | `btn btn-danger` |
| ปุ่มเล็ก | เติม `btn-sm` |
| ปุ่มไอคอนล้วน (แก้ไข ลบ ปิด) | `icon-btn` (+ `icon-btn-danger` สำหรับลบ) |
| ลิงก์ข้อความ | `link-action` / `link-danger` |
| ช่องกรอก / select / textarea | `input` + ป้าย `label` (ผูก `for`/`id` เสมอ) |
| ช่องค้นหา | `search-input` ใน `<label class="relative">` + `AppIcon name="search"` |
| หัวข้อหน้า | `page-title` |
| ฟอร์มยาว (ขอรถ ฯลฯ) | `form-row` (+ `form-row-title`, `form-row-note`, `form-row-body`) - หัวข้อซ้าย ช่องกรอกขวา คั่นด้วยเส้นบาง ห้ามครอบแต่ละแถวด้วยกรอบ || ชิป / ป้ายสถานะกลาง | `chip` (+ `chip-accent`, `chip-solid`) |
| ปุ่มกรอง | `filter-chip` + `aria-pressed` |
| รายการเลือกแนวตั้งข้างเนื้อหา (เช่น เลือกห้องหน้า home) | `rail-btn` + `aria-pressed` |
| ตารางข้อมูล | `data-table` (+ `row-group` / `row-sub` / `row-gap` เมื่อมีลำดับชั้น) |
| Modal | `modal-backdrop` > `modal-panel` > `modal-header` / `modal-body` / `modal-footer` |
| เมนูหลักบน header | `nav-link` + `active-class="nav-link-active"` |
| โครงหน้า (≤1400px กลางจอ) | `page-container` ครอบเนื้อหา, `page-bar` สำหรับแถบ header/เมนูย่อย |
| เมนูย่อยใต้ header | component `SubNav.vue` เท่านั้น (ห้ามเขียนแท็บเอง) |
| ตัวเลขจำนวนงานรอดำเนินการ | `count-badge` (+ `count-badge-float` ลอยมุมปุ่ม); เมนูย่อยใส่ `badge` ใน items ของ SubNav |
| เมนูหล่นกระดิ่งแจ้งเตือน | `notice-menu` > `notice-item` (ผ่าน `NotificationBell.vue`) |

ถ้าจำเป็นต้องมีรูปแบบใหม่ที่ยังไม่มี → **เพิ่ม class ใหม่ใน `style.css` + เพิ่มแถวในตารางนี้** แล้วค่อยใช้ ห้ามเขียนยาวๆ ในไฟล์ `.vue`

## 4. แบบแผนหน้าจอ

**โครงหน้า**: header (โลโก้ + เมนูหลัก) → เมนูย่อย `SubNav` (ถ้ากลุ่มหน้านั้นมี) → เนื้อหา `page-container` (กว้างสูงสุด 1400px อยู่กลางจอ จอเล็กกว่านั้นเต็มจอ padding 16/24px - ห้ามเขียน `max-w-*` + `mx-auto` ครอบทั้งหน้าเอง ให้ใช้ class นี้)
- เมนูย่อย **ตรึงอยู่ใต้ header ไม่เลื่อนตามหน้า** (`sticky top-14`, dev 2026-10-08) และ **ไม่มีเส้นคั่นด้านล่างทั้งแถบ** (dev ไม่ต้องการ); เมนูย่อยทุกรายการต้องมีไอคอน (`icon`) ครบทุกรายการ ผ่าน `SubNav`; รายการที่เปิดอยู่ = ตัวหนา + เส้นใต้หนา 3px สี accent + ไอคอนสี accent
- เมนูหลักบน header: รายการที่เปิดอยู่ = ตัวหนาสี ink (ไม่มีเส้นใต้)

**หัวหน้า**: หน้าที่มีเมนูย่อย (`SubNav`) ไม่แสดงหัวข้อซ้ำกับแท็บที่เลือก - ใส่ `<h1 class="sr-only">` ไว้ให้โปรแกรมอ่านหน้าจอเท่านั้น ถ้าหน้ามีปุ่มหลักให้วางแถวเดียวชิดขวา (มีไอคอน `plus` นำหน้าเมื่อเป็นการเพิ่ม) ส่วนหน้าที่ไม่มีเมนูย่อย (ล็อกอิน ฯลฯ) ใช้ `page-title` ได้ - ห้ามมีบรรทัดสรุปตัวเลขใต้หัวข้อ (ใช้จำนวนในปุ่มกรองแทน)

**แถบเครื่องมือเหนือตาราง**: ปุ่มกรอง `filter-chip` (แสดงจำนวนในปุ่ม) ซ้าย - ย่อ/ขยายทั้งหมด + ช่องค้นหาขวา

**ตาราง**:
- วางแบนบนพื้นขาว ไม่มีกรอบ/เงา/เส้นคั่นทุกแถว; ห่อด้วย `overflow-x-auto` (ห้ามให้หน้าเลื่อนแนวนอน)
- ลดคอลัมน์ที่ข้อมูลซ้ำกับลำดับชั้นหรือบริบท (เช่น ไม่มีคอลัมน์ "ระดับ")
- ข้อมูลลำดับชั้น: แถวแผนก/หัวกลุ่ม = `row-group` (พื้น surface ตัวหนา มุมโค้ง); รายการย่อย = `row-sub` เยื้องพร้อมเส้นเชื่อมโค้ง; คั่นกลุ่มด้วย `row-gap`
- ปุ่มจัดการท้ายแถว = `icon-btn` (edit / trash) เห็นจางๆ ตลอด ชัดตอน hover; ลบไม่ได้ให้ `disabled` พร้อม `title` บอกเหตุผล
- ท้ายตารางบอก "แสดง X จาก Y รายการ" เมื่อมีการกรอง/ค้นหา; ไม่มีข้อมูล → ข้อความกลางตาราง `text-subtle`

**ฟอร์มใน modal**: `label` + `input` เรียงลงมา ปุ่มท้าย `[ยกเลิก = btn-secondary] [บันทึก = btn-primary]` ชิดขวา; error แสดงใต้ฟอร์มสี `text-danger`

**การตอบสนอง (Responsive)**: **จอ laptop ที่เล็กที่สุดคือ 1024px (เช่น 1280px ที่ขยาย 125%) ต้องแสดงผลถูกต้องทุกหน้า** และต้องใช้ได้ที่ 375 / 768 / 1440 / 1920px
- ห้ามหน้าเลื่อนแนวนอนที่ 1024px; ตาราง/ปฏิทินที่กว้างกว่าจอให้ห่อด้วย `overflow-x-auto` ของมันเอง
- **หน้าต่างครึ่งจอ/จอแคบ**: `data-table` มี `min-w-[44rem]` - ต้องอยู่ใน `overflow-x-auto` เสมอ จอแคบจะเลื่อนข้างแทนการบีบคำ; เมนูย่อยเกิน 6 รายการจะลดระยะ/ขนาดอักษรที่ <1024px และขึ้นบรรทัดใหม่เมื่อไม่พอ (ห้ามซ่อนด้วยการเลื่อน); ทดสอบที่ ~820px (ครึ่งจอ 1920) ทุกครั้งที่เพิ่มหน้า
- header + เมนูย่อย **ต้องอยู่บรรทัดเดียว** ที่ 1024–1920px (ห้ามเหลือรายการโดดๆ ลงบรรทัดใหม่): `SubNav` ที่มีเกิน 6 รายการจะซ่อนไอคอนและลดระยะอัตโนมัติเมื่อจอแคบกว่า 1366px - ถ้าเพิ่มรายการเมนูแล้วล้นที่ 1024px ให้ย่อชื่อเมนูหรือจัดกลุ่มใหม่ ไม่ใช่ปล่อยให้ขึ้นบรรทัด
- **ความสูงจอ notebook ที่เล็กที่สุด = 560px** (viewport หลังหักแถบเบราว์เซอร์/taskbar ของจอ 1280×720 หรือ 1920×1080 ที่ขยาย 150%; จอ 1366×768 ได้ประมาณ 600–650px): ห้ามกำหนดความสูงตายตัวทั้งหน้า (`h-screen`, `h-[NNNpx]` ครอบหน้า) - ให้หน้าเลื่อนแนวตั้งได้ตามธรรมชาติ; header สูงคงที่ 56px และเกาะบน (sticky) เท่านั้น; modal ต้องมี `max-h-[90vh]` พร้อมเลื่อนภายใน (ใช้ `modal-panel` + `modal-body overflow-y-auto`) เพื่อให้ปุ่มบันทึกไม่หลุดจอ
- **หน้าที่เป็นปฏิทิน/ภาพรวม (เช่น หน้าแรก) ต้องเห็นครบในหน้าจอเดียว**: ให้หน้าสูงอย่างน้อยเท่าจอ (`min-h-[calc(100dvh-3.5rem)] flex flex-col`) แล้วให้ปฏิทินยืดตามพื้นที่ที่เหลือ (`flex-1` + จำนวนแถวตามสัปดาห์จริงของเดือน 4–6 แถว ห้ามบังคับ 6 แถวเสมอจนเหลือแถวว่าง) ช่องวันสูงต่ำสุด 56px (`min-h-14`) - ส่วนหัวของหน้าต้องกะทัดรัด (หัวข้อ 1 บรรทัด + แถบเครื่องมือ 1 บรรทัด)
- คอลัมน์รองซ่อนบนจอเล็กด้วย `hidden sm:table-cell`; ห้ามมี scrollbar ในเมนู
- วิธีตรวจ: เปิดหน้านั้นในกรอบ (iframe/DevTools device mode) กว้าง 1024px แล้วดูว่าไม่มีแถบเลื่อนแนวนอนของหน้า

**ข้อความ**: 2 ภาษาผ่าน vue-i18n ตามเดิม (REQUIREMENTS § 7); ข้อความปุ่มบอกสิ่งที่จะเกิดจริง ("บันทึก", "ลบ") ข้อความ error บอกวิธีแก้

## 5. ห้าม (ตัวตรวจจะแจ้งผิด)

- เขียนปุ่มเองด้วย `bg-slate-900 … text-white px-…` → ใช้ `btn btn-primary`
- เขียนปุ่มรองเองด้วย `border-slate-300 … hover:bg-slate-50` → ใช้ `btn btn-secondary`
- เขียนช่องกรอกเองด้วย `border-slate-300 … focus:outline-none` → ใช้ `input`
- เขียน modal เองด้วย `bg-white shadow-xl rounded-*` → ใช้ `modal-*`
- ไฟล์ใหม่ใช้ `slate-*` → ใช้ token (`text-ink`, `border-line` …)
- การ์ดมีเงา/กรอบรอบตารางหรือเนื้อหาหลัก, มุมเหลี่ยมสนิท, เพิ่มสีเน้นตัวที่ 2, อีโมจิเป็นไอคอน

## 6. Checklist ก่อน commit (ทุกงาน UI)

- [ ] ใช้ token / component class ตามข้อ 2–3 ทั้งหมด ไม่มี class ปุ่ม/ช่องกรอก/modal เขียนเอง
- [ ] หน้าตาตรงกับหน้าจัดการแผนก (ปุ่ม, ช่องกรอก, ตาราง, modal, เมนูย่อย)
- [ ] ดูที่ **1024px (laptop เล็กสุด)** / 1440 / 1920px ไม่มี scrollbar แนวนอนของหน้า และ header/เมนูย่อยอยู่บรรทัดเดียว; มือถือ 375 / แท็บเล็ต 768 ใช้ได้
- [ ] ไม่มีข้อความ hardcode: ทุกข้อความเป็น key ครบทั้งไทย/อังกฤษ (`npm run lint:i18n` ผ่าน)
- [ ] `npm run lint:ui` ผ่าน, `npm run lint` ไม่มี error, `npm run build` ผ่าน
- [ ] ถ้าเพิ่ม component class ใหม่ → เพิ่มลงตารางข้อ 3 ในเอกสารนี้ด้วย

## 7. การตรวจอัตโนมัติ (`frontend/scripts/check-ui-style.mjs`)

- ตรวจ 4 รูปแบบที่ห้าม (ปุ่มหลัก/ปุ่มรอง/ช่องกรอก/modal เขียนเอง) ในทุกไฟล์ `.vue`
- ตรวจ `slate-*` ในไฟล์ใหม่ (ยังไม่ commit) และไฟล์ที่ขึ้นทะเบียนใน `STRICT_FILES` - ย้ายหน้าเก่าเข้าระบบใหม่เมื่อไหร่ ให้เพิ่มชื่อไฟล์ใน `STRICT_FILES`
- `scripts/ui-style-baseline.json` = จุดผิดกติกาเดิมที่ยอมให้ค้าง (ตอนนี้ **0**) - ห้ามเพิ่ม; ห้ามรัน `--baseline` เพื่อ "ปิดปาก" ตัวตรวจ

## 8. สถานะการย้ายหน้าเก่า

- ✅ ย้ายแล้ว: header/เมนูหลัก, เมนูย่อย 3 กลุ่ม (admin / จองห้อง / ขอรถ), หน้าจัดการแผนก, และปุ่ม/ช่องกรอก/ป้าย/modal ที่ตรงแบบในทุกหน้าถูกแปลงเป็น class กลางแล้ว
- ⏳ ยังเป็นสไตล์เดิมที่ปรับสเกลสีให้แล้ว (ตารางเก่า, การ์ดมีกรอบ, ชิปสถานะ): เมื่อแตะแก้หน้าไหน ให้ย้ายหน้านั้นให้เป็นแบบหน้าจัดการแผนก (ตารางแบน `data-table`, ไม่มีกรอบ/เงา) แล้วเพิ่มชื่อไฟล์ใน `STRICT_FILES`
