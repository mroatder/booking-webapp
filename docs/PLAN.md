### M0 - Project Scaffolding
- ตั้งโครง `frontend/` (Vue 3 + Vite + JavaScript + Router + Pinia + Tailwind + vue-i18n skeleton พร้อมไฟล์ th.json/en.json เปล่า)
- ตั้งโครง `backend/` (Express + JavaScript, โครงสร้าง modules ตาม ARCHITECTURE.md, mssql connection pool, migration runner)
- ตั้งค่า lint/format ทั้งสองฝั่ง
- **ทดสอบ**: `npm run dev` ทั้งสองฝั่งรันได้, backend มี `/health` ตอบ 200

### M1 - Auth (AD + Local)
- Migration ตาราง `USERS`
- LDAP bind (ldapjs) + local bcrypt auth, JWT httpOnly cookie, middleware `requireAuth`/`requireRole`
- หน้า Login, route guard ฝั่ง frontend ตาม role
- **ทดสอบ**: unit test auth flow (mock LDAP), login ด้วย local account จริงผ่าน UI, เข้าหน้า admin ไม่ได้ถ้าไม่ใช่ Admin

### M2 - Room + User Management (Admin)
> เพิ่ม User Management เข้ามาใน milestone นี้ทีหลัง (ตกหล่นตอนเขียนแผนครั้งแรก - Auth ใน M1 ทำแค่ login ไม่ได้ทำหน้าจัดการผู้ใช้)
- Migration ตาราง `ROOMS`
- API CRUD ห้อง + regenerate tablet token (~~token ต่อห้อง~~ → ย้ายไปอุปกรณ์ใน M6+)
- API `GET/POST/PUT/DELETE /api/users` (Admin เท่านั้น) สำหรับสร้าง/แก้ไข local account และกำหนด role
- หน้าจัดการห้อง (Admin), หน้าจัดการผู้ใช้ (Admin), layout หลัก + ตัวสลับภาษา (ใช้ได้ทุกหน้าตั้งแต่ milestone นี้)
- **ทดสอบ**: CRUD ห้อง + CRUD ผู้ใช้ผ่าน UI ครบ, สลับภาษาแล้วข้อความเปลี่ยนถูกต้อง ไม่มี text ตกหล่น

### M3 - Room Booking + กันชน
- Migration ตาราง `ROOM_BOOKINGS`
- API สร้าง/แก้ไข/ยกเลิกการจอง + recurring weekly + transaction lock (UPDLOCK/HOLDLOCK) กันจองชน
- หน้าปฏิทิน/ค้นหาห้องว่าง, หน้าจองห้อง, หน้ารายการจองของฉัน
- **ทดสอบ**: unit test จองชนกันต้อง reject, integration test ยิง request พร้อมกัน (concurrency) ต้องไม่มีการจองซ้อนหลุดผ่าน, จองซ้ำรายสัปดาห์ยกเลิกทั้งชุด/เฉพาะครั้งได้

### M4 - เช็คอิน + ปล่อยห้องอัตโนมัติ
- API `/bookings/:id/checkin`
- Cron job ตรวจการจองที่เลยเวลา 10 นาทีแล้วยังไม่เช็คอิน → เปลี่ยนสถานะ `AutoReleased`
- Logic แจ้งเตือนกรณีใช้เกินเวลาที่จอง (แจ้งทั้งสองฝ่าย ไม่ตัดสิทธิ์)
- **ทดสอบ**: unit test cron logic (เช็คอินทันเวลา / เลยเวลา / ใช้เกินเวลา)

### M5 - Tablet Display
- API public `/tablet/:token/status` (จริง: `/tablet/display/:token` - ใน M6+ token เป็นของอุปกรณ์ + มีปฏิทินรายเดือน)
- หน้าจอแสดงผลห้อง (responsive สำหรับจอ tablet), auto-refresh
- **ทดสอบ**: เปิดหน้าด้วย token จริงจากเบราว์เซอร์มือถือ/tablet เห็นสถานะถูกต้อง, token ผิด/ถูก revoke แล้วเข้าไม่ได้

### M6 - Vehicle Requests + Driver/Vehicle Management
- Migration ตาราง `DRIVERS` (ไม่ผูกกับ USERS - คนขับไม่มี login), `VEHICLE_REQUESTS`
- API ส่งคำขอรถ (employee), จัดการคนขับ (Admin), มอบหมายคนขับ+ประเภทรถ (Admin) พร้อมกันชนช่วงเวลาคนขับ (เช็คจาก vehicle_requests ที่มอบหมายไปแล้ว)
- หน้าฟอร์มขอรถ, หน้ารายการคำขอของฉัน, หน้าจัดการคำขอรถ (Admin), หน้าจัดการคนขับ + ปฏิทินคนขับ (Admin ดูเองเท่านั้น)
- **ทดสอบ**: unit test กันชนคนขับคนเดียวกันถูกมอบหมายซ้อนเวลา, จองรถ end-to-end ผ่าน UI

### M6+ - ปรับเพิ่มหลัง M6 (ไม่อยู่ในแผนเดิม - dev ขอระหว่างทาง, เสร็จแล้ว, commit 2026-09-30)
- **ขอรถ**: พนักงานทุกคนขอได้ (รวมรถโอที), เลือกผู้โดยสารได้เฉพาะแผนกหลัก (ตาราง Departments), รูปแบบการเดินทาง, แผนที่จุดรับ/ปลายทางแยก + ติ๊ก "ที่บริษัท", กันพนักงานมีชื่อซ้ำในคำขอที่เวลาทับกัน
- **รถโอที/สายรถ**: สายรถ + จุดจอด + รถ/คนขับประจำ, ผู้โดยสารรถรับส่ง, แนะนำรถจากสาย, หน้าจัดการคำขอแบบรวมตามสาย + ใบรายชื่อ + จัดรถทั้งเที่ยว, โอทีเที่ยวเดียวกันใช้รถร่วมกันได้
- **จัดการข้อมูล**: ลบจริงเฉพาะรายการที่ไม่มีประวัติ (คนขับ/รถ/ผู้ให้บริการ/ห้อง) ไม่งั้นปิดใช้งาน, ห้องปิดใช้งานได้, อุปกรณ์เป็นตารางของตัวเอง (เพิ่ม/แก้/ลบ/ผูกห้อง)
- **จอ tablet**: ภาษาอังกฤษเท่านั้น, ธีมแบบจอรถ Tesla, ปฏิทินรายเดือนของห้อง (กลับหน้าสถานะเองใน 5 นาที), responsive - เครื่องหลัก Samsung Galaxy Tab A11+ แนวนอน
- **ทดสอบ**: backend 233 test (รวม integration กับ DB จริง: ใช้รถร่วมเที่ยวเดียวกัน, จัดทั้งเที่ยว, ผู้โดยสารซ้ำ, ลบแบบเช็คประวัติ), ตรวจหน้าจอในเบราว์เซอร์ (ยังไม่ได้ทดสอบด้วยบัญชีที่ไม่ใช่ Admin)
